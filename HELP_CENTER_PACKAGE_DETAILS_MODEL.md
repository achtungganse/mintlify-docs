# eBanano — модель сведений «О пакете»

**Статус:** Product/UX baseline  
**Дата:** 2026-09-18

Цель экрана — не показать максимум технических данных, а помочь пользователю понять:
1. что он покупает;
2. когда пакет начнёт действовать;
3. как будет расходоваться трафик;
4. можно ли продолжить использование;
5. есть ли важные ограничения.


## Два разных контекста: до покупки и после покупки

Сведения о пакете нельзя проектировать как один универсальный набор полей.

### До покупки

Пользователь решает, подходит ли ему предложение. Приоритет:

1. объём/тип трафика;
2. срок;
3. правило начала действия;
4. покрытие;
5. ограничение после дневного лимита/поведение после лимита;
6. сети/операторы;
7. пополнение support;
8. ограничения.

### После покупки / в «Моя eSIM»

Пользователь уже не выбирает тариф, а управляет конкретной eSIM. Здесь важнее:

1. текущий status eSIM/profile;
2. осталось трафика;
3. когда истекает текущий пакет;
4. когда данные последний раз обновлялись;
5. можно ли пополнить;
6. выбранный автопродление пакет;
7. цена следующего автопродления;
8. автопродление active/paused;
9. причина паузы;
10. APN/action only if manual setup is required;
11. IP routing как дополнительная техническая информация.

Один и тот же параметр может иметь разный текст до и после покупки. Например до покупки: «Срок — 30 дней после первого подключения к сети». После активации: «Действует до 24 октября».

## Показывать всегда

### Интернет / тип пакета

Показывать реальное поведение, а не provider dataType.

Примеры:
- 10 ГБ на весь срок;
- 3 ГБ в день;
- 3 ГБ в день, затем скорость до 1 Мбит/с;
- безлимитный дневной пакет.

Если после дневного лимита действует ограничение после дневного лимита, это должно быть видно до покупки.

### Срок действия

Показывать validity отдельно от момента активации.

### Начало действия

Показывать отдельной строкой:
- после первого подключения к сети;
- сразу после установки;
- сразу после покупки.

### Покрытие

Для одной страны — страна. Для регионального/глобального предложения — доступ к полному списку стран. Название региона не заменяет покрытие.

## Показывать условно

### Пополнение

Только если пополнение поддерживается.

В зависимости от продукта:
- можно пополнить трафик;
- можно продлить срок.

### Автопродление

Только для eSIM, где пополнение поддерживается и eBanano разрешает renewal.

В управлении конкретной eSIM нужно показывать:
- выбранный пакет;
- цену следующего пополнения;
- триггер менее 10%;
- состояние включено / приостановлено;
- возможность отключить;
- причину паузы.

Если выбранный пакет исчез, система не выбирает замену автоматически.

### ограничение после дневного лимита / поведение после лимита

Для снижение скорости после дневного лимита и остановка интернета после дневного лимита обязательно показывать:
- high-speed allowance;
- что произойдёт после лимита;
- скорость после лимита, если она известна.

### Сети и операторы

Показывать, если данные нормализованы.

Пример:
- Сеть: 4G / 5G
- Операторы: Turkcell, Vodafone TR

Для региональных тарифов детали лучше раскрывать по стране.

### IP-адрес / IP exit

Показывать в дополнительном блоке, если provider значение удалось безопасно нормализовать.

Текст по смыслу:
«IP-адрес может определяться в другой стране из-за маршрутизации оператора. На работу мобильного интернета это обычно не влияет.»

Raw значения вроде FR/NL/UK или Europe не выдавать как точную страну IP.

### Особые ограничения

Показывать только нормализованные ограничения, влияющие на покупку, активацию, использование или возврат.

## Не показывать по умолчанию

### APN

У eSIMAccess APN обычно настраивается автоматически. Если конкретному продукту нужен ручной APN, это должно появляться как действие в установке/подключении, а не как обычная характеристика пакета.

### QR / SM-DP+ / Activation Code

Это чувствительные installation data купленной eSIM, не свойства тарифа.

### ICCID / IMSI / provider slug / packageCode

Не использовать как обычные user-facing package characteristics.

### Provider price / retailPrice / raw codes

Пользователь видит цену eBanano, не технические цены поставщика.

## Предлагаемый порядок в sheet «О пакете» после покупки

### Основные условия
1. Интернет — объём/тип трафика.
2. Срок действия.
3. Начало действия.
4. Покрытие.

### Продолжение использования
5. Пополнение.
6. Автопродление.

### Связь
7. Сеть.
8. Операторы.
9. ограничение после дневного лимита / дневное ограничение.

### Дополнительно
10. IP-маршрутизация.
11. Особые ограничения.

## Оценка текущего макета

На текущем макете есть:
- срок действия — оставить;
- пополнение — оставить условно;
- автопродление — оставить условно;
- IP-адрес — оставить в дополнительном блоке.

Не хватает:
- объёма и модели трафика;
- отдельного правила активации;
- покрытие;
- ограничение после дневного лимита/поведения после дневного лимита;
- сетей/операторов, когда они доступны.

Эти параметры сильнее влияют на ожидания пользователя, чем IP routing.

## Provider → public mapping

Основные входные данные eSIMAccess:
- dataType → traffic policy;
- volume → allowance;
- fupPolicy → throttling/cutoff;
- duration + durationUnit → validity;
- activeType → activation;
- supportTopUpType → пополнение support/mode;
- locationNetworkList → operators/networks;
- speed → network labels;
- ipExport → IP exit;
- descriptionList → reviewed features;
- saleNote → normalized restrictions;
- APN → instruction only when manual action is required.

## Главное UX-правило

Если поле не меняет решение пользователя и не требует действия, его не нужно показывать только потому, что поставщик его вернул.

Если поле может запустить срок раньше, изменить скорость, отключить интернет после лимита, ограничить страны или повлиять на возможность пополнения — оно должно быть видно до покупки.


## Runtime usage

eSIMAccess позволяет получать usage/remaining validity по API и присылает low-data/low-validity webhooks. Архитектура eBanano отдельно учитывает, что usage может обновляться с задержкой, поэтому в «Моя eSIM» желательно показывать не просто число остатка, а также отметку вида «Обновлено …».

Нельзя обещать пользователю realtime balance, если источник данных не realtime.


## Сети и операторы: как показывать

Если поставщик возвращает для конкретного тарифа несколько поддерживаемых операторов, их можно показывать прямо в карточке или деталях тарифа.

Рекомендуемый вариант интерфейса:

**Turk Telecom — 5G  (+ ещё 2)**

По нажатию открывается список всех поддерживаемых сетей для этой страны.

Важно:
- список берётся только из данных конкретного тарифа;
- если поставщик не возвращает надёжный список сетей, блок не показывается;
- наличие 5G означает, что тариф поддерживает доступ к 5G у указанного оператора, но не гарантирует 5G в любой точке;
- по умолчанию телефон должен выбирать поддерживаемую сеть автоматически;
- ручной выбор сети — это запасной шаг при проблемах с подключением, а не обычная настройка для каждого пользователя;
- при ручном выборе пользователь должен выбирать только сеть, указанную eBanano как поддерживаемую для его тарифа.

Такой подход совпадает с логикой Airalo: список доступных операторов показывается в деталях eSIM, а ручной выбор используется, если автоматическое подключение не сработало.

Для eSIMAccess техническая возможность также подтверждается: профиль содержит список разрешённых операторских сетей, а поставщик рекомендует ручной выбор сети как один из шагов диагностики.
