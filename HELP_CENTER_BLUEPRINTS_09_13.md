# UX-каркасы Help Center eBanano — статьи 9–13

**Статус:** Draft for content design  
**Дата:** 2026-09-18  
**Основание:** [HELP_CENTER_ARCHITECTURE.md](HELP_CENTER_ARCHITECTURE.md), [HELP_CENTER_CONTENT_MATRIX.md](HELP_CENTER_CONTENT_MATRIX.md)

Этот блок покрывает путь от установки профиля до работающего интернета в поездке.

Ключевой UX-принцип: пользователь не обязан понимать внутреннюю разницу между installation, activation, network registration, roaming и mobile data. Он видит только своё состояние:

1. eSIM ещё не установлена;
2. установка не получается;
3. eSIM установлена, я приехал и хочу подключиться;
4. хочу оставить домашнюю SIM вместе с eSIM;
5. eSIM установлена, но интернет работает неправильно.

---

# 9. Как установить eSIM

## Пользовательский вопрос

> «Я уже купил eSIM. Как добавить её на телефон?»

## UX-цель

Дать всю нормальную установку на одной странице независимо от устройства и способа установки.

Пользователь не должен отдельно открывать:

- «iPhone»;
- «Android»;
- «QR на этом же телефоне»;
- «Ручная установка».

Это варианты **одной задачи**, а не четыре самостоятельных намерения.

## Что должно быть на первом экране

### Заголовок

**Как установить eSIM**

### Короткий ответ

> Подключись к стабильному интернету, открой данные своей eSIM и выбери инструкцию для своего телефона. Если QR-код открыт на этом же устройстве, второй экран может не понадобиться.

Сразу после — короткий prerequisite checklist:

- устройство уже проверено на поддержку eSIM;
- понятен момент активации тарифа;
- есть стабильный интернет;
- открыты данные именно нужного заказа;
- установка выполняется на устройстве, где eSIM будет использоваться.

Для первых двух пунктов допустимы короткие inline-ссылки на №2 и №4. Не повторять их содержание.

## Структура страницы

### Блок 1. Выбери устройство

**Формат:** `Tabs`.

Основные Tabs:

- **iPhone / iPad**
- **Samsung Galaxy**
- **Google Pixel**
- **Другой Android**

Внутри каждого Tab — полный нормальный путь установки QR-кодом.

### Требование к Steps

Каждый Tab должен заканчивать установку одинаковым проверяемым состоянием:

> eSIM появилась в списке SIM/линий устройства.

Это критерий успешной установки. Наличие сигнала или интернета на этом этапе не использовать как критерий.

### Блок 2. QR-код открыт на этом же телефоне

Этот блок идёт **после основной инструкции**, а не отдельной статьёй.

**Формат:** `Tabs` только там, где способы реально отличаются.

- iPhone: системная возможность использовать QR с экрана/из изображения — только для подтверждённых версий iOS;
- Samsung: выбор изображения из Gallery, если поддерживается;
- другие Android: проверить наличие выбора изображения;
- если функция недоступна → второй экран или ручная установка.

Не писать общие фразы вроде «на некоторых устройствах можно» без практического следующего действия.

### Блок 3. Установка вручную

**Формат:** сначала объяснить, какие данные пользователь может увидеть:

- SM-DP+ Address;
- Activation Code;
- Confirmation Code только если он реально предоставлен.

Затем `Tabs` по устройствам.

Ключевые правила:

- копировать значения без изменений;
- не подставлять случайные данные;
- не показывать реальные activation data в примерах;
- не отправлять их публично.

### Блок 4. Как понять, что всё установилось

Короткий checklist:

- профиль появился в настройках SIM;
- его можно отличить по названию/метке;
- телефон больше не предлагает «добавить» этот же профиль как единственное подтверждение;
- интернет может ещё не работать — это не значит, что установка не удалась.

### Блок 5. Что делать после установки

Развилка по состоянию:

- **До поездки ещё есть время** → не продолжать настройку вслепую; проверить timing в №4.
- **Уже в стране назначения** → №11.
- **Установка не завершилась или есть ошибка** → №10.

Максимум три компактных маршрута, потому что это реальные состояния, а не декоративный footer.

## Что поглощается

- `installation/overview.mdx` — prerequisite часть;
- `installation/ios.mdx`;
- `installation/android.mdx`;
- `installation/qr-on-same-phone.mdx`;
- `installation/manual.mdx`.

Пять страниц становятся одной.

## Что не должно попасть сюда

- troubleshooting ошибок установки;
- «Нет сети»;
- APN;
- Data Roaming;
- выбор оператора;
- подробная работа домашней SIM;
- refund.

## Нужные Mintlify-компоненты

- `Tabs` — устройство;
- `Steps` — установка;
- `Info` — version/region caveats;
- `Warning` — только для чувствительных activation data или потенциально невосстановимой ошибки;
- короткие anchor sections для same-phone/manual methods.

Не делать nested Tabs глубже одного уровня, если это ухудшает мобильное чтение. Лучше отдельные подзаголовки внутри device Tab.

## Критерий завершения сценария

Пользователь должен закончить статью в одном из двух состояний:

1. eSIM появилась в настройках устройства;
2. установка не завершилась → он точно понимает, что ему нужна статья №10.

# 10. Не получается установить eSIM

## Пользовательский вопрос

> «Я пытаюсь добавить eSIM, но QR-код или установка не работают».

## UX-цель

Определить **install state** до любых повторных попыток.

Главный риск текущего контента — пользователь может бесконечно повторять сканирование, удалить частично установленный профиль или попытаться перенести его на другое устройство.

Поэтому диагностика начинается не с «попробуй ещё раз», а с вопроса:

> **Профиль уже появился в настройках телефона?**

## Что должно быть на первом экране

### Заголовок

**Не получается установить eSIM**

### Первый `Warning`

> Не удаляй появившийся профиль и не сканируй QR-код снова много раз. Сначала определи, на каком этапе остановилась установка.

### Маршрутизатор симптомов

**Формат:** Cards с anchor links или простой список.

- **QR-код не распознаётся**
- **После QR появляется ошибка**
- **Пишет, что код уже использован**
- **Установка прервалась**
- **eSIM уже появилась в настройках**
- **Я удалил eSIM**
- **Установил eSIM на другой телефон**

Это наблюдаемые симптомы, а не технические статусы backend.

## Структура страницы

### Блок 1. Сначала проверь, нет ли eSIM уже в телефоне

Это должна быть первая реальная проверка для большинства веток.

Если профиль есть:

- установка считается завершённой на уровне устройства;
- не удалять его;
- если проблема теперь в сети/интернете → №13;
- если профиль установлен на неправильное устройство → соответствующая ветка ниже.

### Ветка: QR-код не распознаётся

Проверить:

- открыт ли правильный QR;
- виден ли он полностью;
- не пытается ли пользователь сканировать экран того же телефона;
- поддерживает ли устройство выбор QR из изображения;
- доступна ли ручная установка.

Если QR просто не читается визуально — можно сменить метод установки.

Не вести сразу в support.

### Ветка: появляется ошибка / код уже использован

Сначала определить:

- профиль уже установлен?
- использовались ли данные установки ранее?
- это тот же заказ?
- не была ли установка выполнена на другом устройстве?

Если code status не может быть определён на клиенте — не советовать повторять код. Перейти к support handoff с exact error text.

### Ветка: установка прервалась

Порядок:

1. проверить список SIM;
2. проверить интернет;
3. сохранить error message;
4. если профиля нет — одна безопасная повторная попытка допустима только если provider semantics это позволяют;
5. если профиль появился частично/неясно — не удалять его, support.

Фраза «повтори один раз» должна попасть в финальный текст только после подтверждения поведения текущего поставщика.

### Ветка: я удалил eSIM

Поглощает `deleted-esim.mdx`.

Порядок:

1. убедиться, что линия действительно удалена, а не выключена;
2. открыть исходный заказ;
3. не предполагать, что QR reusable;
4. проверить возможность повторной установки по конкретному профилю;
5. support, если продукт сам не умеет выдать разрешённый reinstall.

### Ветка: установил не на тот телефон

Поглощает `wrong-device.mdx`.

Главное:

- не удалять профиль с первого телефона «чтобы освободить QR»;
- не пытаться повторно сканировать его на втором;
- проверить совместимость нужного телефона;
- transfer/reissue/reinstall зависит от профиля и поставщика;
- передать support оба device contexts.

## Блок «Когда уже нужен support»

Показать конкретные триггеры:

- код сообщает «used/invalid», а профиля нет;
- профиль частично появился и состояние неясно;
- профиль удалён, а self-service reinstall не подтверждён;
- eSIM установлена не на то устройство;
- ошибка повторяется после базовых безопасных проверок.

Короткий checklist данных:

- order ID;
- модель телефона;
- точный текст ошибки;
- скриншот;
- какой способ установки использовался;
- появился ли профиль в SIM settings.

Полный способ обращения → №20.

## Что не входит

- activation after successful install;
- «Нет сети»;
- slow internet;
- roaming/APN;
- refund decision.

## Что поглощается

- `troubleshooting/install-failed.mdx`;
- `troubleshooting/deleted-esim.mdx`;
- `troubleshooting/wrong-device.mdx`.

## Нужные Mintlify-компоненты

- `Warning` в начале;
- Cards/anchors для symptom routing;
- `Steps` внутри веток;
- `Accordion` только для вторичных edge cases, не для основной диагностики.

## Критерий завершения сценария

Пользователь должен установить **состояние профиля**, а не просто получить очередной совет «попробуй снова».

# 11. Как подключить eSIM после приезда

## Пользовательский вопрос

> «eSIM уже установлена. Я приехал. Что нужно включить, чтобы появился интернет?»

## UX-цель

Одна страница должна провести пользователя от установленного профиля до проверки мобильного интернета.

Текущая архитектура разбивает одну последовательность на `connect-after-arrival`, `switching-networks`, `data-roaming` и частично `no-data-connection`. Это нужно убрать.

## Что должно быть на первом экране

### Заголовок

**Как подключить eSIM после приезда**

### Короткий ответ

> Включи eSIM, выбери её для мобильных данных и выполни настройки, указанные для твоего тарифа. Затем проверь, появилась ли сеть и работает ли интернет без Wi‑Fi.

Сразу под ним — `Info`:

> eSIM должна быть уже установлена. Если профиль ещё не добавлен на телефон, сначала открой «Как установить eSIM».

## Основная последовательность

### Шаг 1. Проверь страну и состояние тарифа

Только необходимый минимум:

- страна входит в coverage купленного предложения;
- тариф ещё применим по сроку;
- activation rule позволяет/ожидает подключение сейчас.

Не пересказывать №3 и №4.

### Шаг 2. Включи линию eSIM

**Формат:** `Tabs` по устройствам внутри этого шага.

Tabs:

- iPhone;
- Samsung;
- Google Pixel;
- другой Android — только generic safe guidance.

### Шаг 3. Выбери eSIM для мобильных данных

Это текущая ключевая часть `switching-networks.mdx`.

Показать device-specific путь прямо здесь.

Пользователь не должен переходить в отдельную статью ради выбора data line.

### Шаг 4. Включи Data Roaming, если он нужен этому тарифу

Поглощает `data-roaming.mdx`.

Нужно объяснить ровно столько:

- travel eSIM может подключаться через партнёрскую сеть;
- поэтому у конкретного тарифа может требоваться Data Roaming;
- включать его нужно **на eSIM eBanano**, не на домашней SIM;
- проверить условие конкретного тарифа.

Пути для устройств показывать прямо здесь.

Не делать отдельную статью «Data Roaming».

### Шаг 5. Дождись сети

Показать ожидаемый результат:

- название/индикатор оператора;
- signal bars;
- отсутствие «Нет сети».

Можно кратко рекомендовать airplane mode только если регистрация не обновляется, но это уже пограничный troubleshooting. Основная диагностика остаётся №13.

### Шаг 6. Проверь APN, только если он указан

Очень важно не превращать APN в обязательный шаг для всех.

Формулировка:

> Если в данных тарифа указан APN или автоматическая настройка не была применена, введи значение точно как указано. Если APN не указан, не придумывай его.

Device-specific путь можно дать в компактном `Accordion` или Tabs.

### Шаг 7. Проверь мобильный интернет

- отключить Wi-Fi;
- открыть простой сайт/приложение;
- убедиться, что трафик идёт через нужную SIM.

## Результат: что ты видишь?

Вместо четырёх footer Cards — один маленький decision block:

- **Интернет работает** → готово.
- **Пишет «Нет сети»** → №13, anchor «Нет сети».
- **Сеть есть, но интернет не работает** → №13, anchor «Сеть есть, данных нет».
- **Интернет есть, но медленный** → №13, anchor «Медленно».

Если Mintlify/маршрутизация позволяют, ссылки должны вести сразу на нужный anchor одной diagnostic article.

## Что не входит

- подробная Dual SIM безопасность → №12;
- full troubleshooting → №13;
- установка → №9;
- activation theory → №4.

## Что поглощается

- `using-esim/connect-after-arrival.mdx` — основа;
- `using-esim/data-roaming.mdx` — полностью;
- часть `using-esim/switching-networks.mdx` про data line;
- APN basic setup из `no-data-connection.mdx` — только как условный нормальный setup step.

## Нужные Mintlify-компоненты

- один `Steps` для всей последовательности;
- `Tabs` внутри шагов по устройствам;
- `Info` про roaming;
- `Accordion` для APN только если нужно экономить вертикальное пространство;
- anchors на №13.

Не использовать отдельную Card после каждого шага.

## Критерий завершения сценария

После страницы пользователь либо имеет мобильный интернет, либо может однозначно выбрать один наблюдаемый симптом для №13.

# 12. Как пользоваться eSIM вместе с основной SIM

## Пользовательский вопрос

> «Я хочу интернет через eBanano, но оставить свой обычный номер включённым».

## UX-цель

Объяснить Dual SIM как пользовательскую конфигурацию и отдельно защитить от случайного data roaming домашней SIM.

Эта статья нужна отдельно от №11, потому что её intent существует и **до**, и **во время**, и **после** подключения eBanano.

## Что должно быть на первом экране

### Заголовок

**Как пользоваться eSIM вместе с основной SIM**

### Короткий ответ

> Если телефон поддерживает одновременную работу линий, можно оставить домашнюю SIM для звонков и SMS, а eBanano выбрать для мобильного интернета. Главное — проверить, какая SIM используется для данных.

Сразу после — `Warning`:

> Домашний оператор может отдельно тарифицировать звонки, SMS и мобильный роуминг. eBanano не управляет тарифами основной SIM.

## Структура страницы

### Блок 1. Какая SIM за что отвечает

**Формат:** таблица.

| Задача | Рекомендуемая линия |
| --- | --- |
| Мобильный интернет в поездке | eBanano |
| Домашний номер | Основная SIM, если нужен и условия оператора устраивают |
| Звонки/SMS | Зависят от основной SIM и оператора |

Не обещать бесплатные входящие SMS/звонки.

### Блок 2. Настрой мобильный интернет через eBanano

Можно использовать более короткие `Tabs` по устройствам, чем в №11.

Здесь допускается минимальное повторение самой настройки data line, потому что без неё сценарий не завершить.

Но не повторять весь arrival flow, roaming и APN.

### Блок 3. Отключи автоматическое переключение данных, если оно может использовать домашнюю SIM

Объяснить системную функцию вроде Cellular Data Switching только по подтверждённым платформам.

Главная мысль:

- телефон не должен автоматически уходить на домашнюю SIM для data, если пользователь хочет избежать roaming charges.

### Блок 4. Что делать с Data Roaming на основной SIM

Развести две линии:

- travel eSIM может требовать Data Roaming;
- домашней SIM Data Roaming обычно не нужен для eBanano;
- включение/выключение зависит от желания использовать мобильные данные домашнего оператора.

### Блок 5. А звонки и SMS продолжат работать?

Короткий ответ с caveat:

- технически линия может оставаться активной;
- фактическая доступность и стоимость зависят от домашнего оператора, VoLTE/Wi‑Fi Calling, страны и устройства;
- не обещать универсальное поведение.

### Блок 6. Как проверить, через что сейчас идёт интернет

Практический mini-check:

- открыть data SIM setting;
- временно отключить Wi-Fi;
- проверить выбранную line;
- при необходимости посмотреть system indicator.

Не советовать «потратить данные для теста» без необходимости.

### Блок 7. После поездки

Только короткий bridge:

- вернуть домашнюю SIM как data line;
- eBanano можно выключить;
- удалять профиль необязательно.

Полный lifecycle профиля → №15.

## Что не входит

- полный arrival setup;
- troubleshooting;
- тарифы домашнего оператора;
- управление множеством eSIM после поездки.

## Что поглощается

- основная Dual SIM часть `using-esim/switching-networks.mdx`;
- safety-тексты про домашний roaming из `data-roaming.mdx`.

## Нужные Mintlify-компоненты

- таблица ролей SIM;
- `Tabs`;
- `Warning` про домашнего оператора;
- один bridge в №15.

## Критерий завершения сценария

Пользователь должен точно понимать:

- какая линия используется для интернета;
- зачем остаётся домашняя SIM;
- где возможны расходы домашнего оператора;
- как не дать телефону незаметно переключить data обратно.

---

# 13. eSIM установлена, но интернет не работает

## Пользовательский вопрос

> «eSIM уже есть в телефоне, но с подключением что-то не так».

## UX-цель

Одна diagnostic page должна заменить четыре сегодняшние страницы:

- activation failed;
- no network;
- no data;
- slow internet.

При этом страница не должна превращаться в огромный линейный чек-лист, который каждый пользователь читает целиком.

Решение — **сначала маршрутизация по симптому, потом короткая ветка**.

## Что должно быть на первом экране

### Заголовок

**eSIM установлена, но интернет не работает**

### Короткое уточнение

> Выбери то, что видишь на телефоне сейчас. Проверки отличаются в зависимости от того, есть ли сеть и работает ли передача данных.

### Маршрутизатор симптомов

**Формат:** 5 functional Cards с anchor links.

1. **eSIM не активируется**
2. **Пишет «Нет сети»**
3. **Сеть есть, но интернета нет**
4. **Интернет работает медленно**
5. **Интернет работал и перестал**

Cards должны быть короткими и не повторять решение.

## Общая проверка перед ветками

Не делать общий 10-шаговый checklist.

Разрешены только 2 проверки, которые применимы почти ко всем:

- eSIM — нужная линия/заказ;
- пользователь находится в стране/coverage нужного тарифа.

После этого сразу symptom branch.

---

## Ветка A. eSIM не активируется

### Когда выбирать эту ветку

- профиль установлен;
- пользователь ожидает смену статуса/старта пакета;
- activation condition вроде бы выполнено.

### Порядок

1. открыть activation rule конкретного тарифа;
2. проверить, выполнено ли условие;
3. проверить регистрацию в поддерживаемой сети;
4. проверить, работает ли интернет фактически;
5. если интернет работает, а UI-status запаздывает — не ломать подключение ради статуса;
6. если условие выполнено, но ни status, ни service не работают → support.

Не повторять всю модель purchase/install/activation — inline link на №4.

### Запрещённое действие

`Warning`: не удалять eSIM и не переустанавливать её ради изменения activation status.

---

## Ветка B. Пишет «Нет сети»

### Когда выбирать

Нет имени/индикатора сети, устройство не зарегистрировалось.

### Порядок

1. линия eSIM включена;
2. coverage соответствует текущей стране;
3. airplane mode → reconnect;
4. reboot при необходимости;
5. automatic network selection;
6. попробовать другое место/сигнал;
7. manual network selection только если конкретный тариф/support даёт список допустимых операторов.

### Device-specific section

`Tabs` только для network selection.

Не повторять настройки data line и APN: они не исправляют отсутствие network registration.

### Support data

- страна;
- order ID;
- модель;
- screenshot network status;
- automatic/manual state;
- доступные операторы, если пользователь видел список.

---

## Ветка C. Сеть есть, но интернета нет

### Когда выбирать

Signal/operator есть, сайты/приложения без Wi-Fi не работают.

### Порядок

1. отключить Wi-Fi для чистой проверки;
2. eBanano выбрана data line;
3. Data Roaming включён, если нужен тарифу;
4. airplane mode/reconnect;
5. проверить status/remaining data/validity;
6. APN — только по данным конкретного тарифа;
7. support.

### APN

Это canonical troubleshooting section для неправильного/неприменённого APN.

Показать:

- где искать на iPhone;
- где искать на Android;
- вводить только значения provider/order;
- не менять остальные поля без инструкции.

---

## Ветка D. Интернет работает медленно или нестабильно

### Порядок

1. отключить Wi-Fi и убедиться, что тестируется eSIM;
2. сравнить несколько приложений/сайтов;
3. проверить уровень сигнала и другое место;
4. airplane mode/reconnect;
5. проверить remaining data, validity и ограничения тарифа;
6. проверить FUP, если он указан;
7. временно исключить VPN / data saver / фоновые загрузки;
8. support, если проблема стабильна в разных местах.

Не обещать конкретную скорость.

Не советовать speed test как обязательный первый шаг, если он сам расходует заметный трафик. Если понадобится speed evidence для support, использовать его осознанно.

---

## Ветка E. Интернет работал и перестал

Эта ветка отсутствует в текущей базе как самостоятельный symptom и очень важна.

### Порядок

1. проверить остаток данных;
2. проверить срок действия;
3. проверить FUP/daily allowance;
4. убедиться, что data line не переключилась;
5. проверить наличие сети;
6. reconnect;
7. если package state нормальный → перейти к релевантной ветке B/C/D по текущему симптому.

Таким образом ветка не дублирует всю диагностику, а сначала проверяет причины, характерные именно для «работало раньше».

# Support escalation для всей статьи

Внизу один общий блок вместо повторения support в каждой ветке.

## Когда обращаться

- базовые проверки своей ветки выполнены;
- проблема воспроизводится;
- тариф/coverage подходят;
- дальнейшие действия требуют provider-side проверки.

## Что приложить

- account email;
- order ID;
- страна;
- модель устройства;
- текущий symptom;
- screenshot;
- какие проверки уже выполнены;
- visible network/operator;
- APN только как название/значение, если support это допускает и оно не является секретом.

Полный handoff → №20.

## Что поглощается

- `troubleshooting/activation-failed.mdx`;
- `troubleshooting/esim-not-working.mdx`;
- `troubleshooting/no-data-connection.mdx`;
- `troubleshooting/slow-internet.mdx`.

Четыре страницы становятся одной страницей с пятью symptom branches.

## Нужные Mintlify-компоненты

- functional Cards + anchors в начале;
- `Steps` внутри каждой ветки;
- `Tabs` только там, где device UI реально отличается;
- `Warning` для опасных действий;
- один общий support block.

### Не использовать

- один гигантский `Steps` на все проблемы;
- Tabs «Activation / Network / Internet» — это технические категории, которые пользователь может не понимать;
- Accordions для основных diagnostic steps;
- повторные «Связанные статьи» после каждой ветки.

## Критерий завершения сценария

Пользователь:

1. выбрал симптом по тому, что видит;
2. прошёл только релевантные проверки;
3. либо восстановил интернет;
4. либо дошёл до support с уже собранным диагностическим контекстом.

## Допустимое повторение

Некоторые действия должны кратко повторяться в нескольких сценариях, потому что без них пользователь не завершит задачу.

Например, выбор eSIM как data line:

- полностью входит в normal arrival flow №11;
- кратко повторяется в Dual SIM scenario №12;
- проверяется как troubleshooting step в №13.

Это **не считается вредным дублированием**, если:

1. инструкция короткая;
2. формулировка и UI path поддерживаются из одного reusable MDX fragment;
3. теория не пересказывается заново.

То же правило применить к Data Roaming и device-specific paths.
