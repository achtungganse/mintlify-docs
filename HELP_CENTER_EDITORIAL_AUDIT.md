# Редакторский аудит русского Help Center

**Дата:** 2026-09-18  
**Статус:** Russian baseline ready for product verification

## Итог

Русский Help Center переведён с раздутой тематической структуры на сценарную модель.

Сейчас в публичной русской навигации:

- 1 главная страница-маршрутизатор;
- 19 пользовательских статей;
- 9 логических разделов.

## Что проверено

### Навигация

Порядок соответствует жизненному циклу пользователя:

1. Начало работы.
2. Покупка и заказ.
3. Установка.
4. Подключение в поездке.
5. Если что-то не работает.
6. Использование eSIM.
7. Аккаунт.
8. Bananos и бонусы.
9. Помощь.

### Дублирование

Старые микростатьи поглощены каноническими сценариями.

Ключевые объединения:

- что такое eSIM + что такое eBanano;
- совместимость + блокировка оператора;
- выбор пакета + покрытие + условия пакета;
- способы оплаты + валюта + промокод;
- все варианты установки;
- все ошибки установки;
- подключение + роуминг данных;
- проблемы активации / сети / интернета / скорости;
- обычные вопросы аккаунта;
- loyalty-страницы;
- referral-страницы.

Полных повторов между текущими каноническими страницами не обнаружено.

### Ссылки

Внутренние ссылки всех текущих русских канонических страниц проверены: ссылок на поглощённые страницы не осталось.

В docs.json добавлены 28 редиректов со старых русских URL на новые канонические страницы.

### Язык

Из публичного текста удалены:
- редакторские комментарии;
- внутренние названия поставщика;
- смешение русского текста с Help Center / launch / top-up / renewal и подобной терминологией;
- ненужные ссылки на внутреннюю продуктовую кухню.

Технические сокращения вроде APN используются только там, где пользователь может увидеть такое название в настройках устройства, и рядом объясняются по-русски.

### Устройства

Основные пути установки сверены с актуальными инструкциями Apple, Samsung и Google.

## Главная страница

Создан index.mdx как маршрутизатор по состоянию пользователя.

Основные входы:
- впервые пользуюсь eSIM;
- хочу выбрать пакет;
- уже купил eSIM;
- устанавливаю;
- уже в поездке;
- интернет не работает;
- проблема с оплатой или заказом;
- нужна поддержка.

Дополнительно вынесены остаток/пополнение и аккаунт.

## Что пока не считается готовой продуктовой логикой

### Автопродление

Статус: **в разработке**.

До отдельного продуктового обсуждения не публиковать:
- порог запуска;
- выбор повторного пакета;
- будущую цену;
- поведение при изменении цены;
- неуспешное списание;
- повторы списания;
- уведомления;
- поведение при недоступности пакета;
- правила для пополнения срока вместо трафика.

### Программа лояльности

Статус: **в разработке**.

Нужна отдельная продуктово-финансово-юридическая задача.

### Реферальная программа

Статус: **в разработке**.

Нужна отдельная продуктово-финансово-юридическая задача.

### Удаление аккаунта

Не входит в текущую публичную навигацию.

Отдельная задача должна закрыть:
- пользовательский сценарий;
- активные eSIM;
- автопродление;
- заказы и возвраты;
- финансовые записи;
- хранение и анонимизацию данных;
- возможность отмены удаления.

### Возвраты

Структура статьи готова, но финальные гарантии и юридические формулировки должны пройти сверку с Terms eBanano и правом РК.

### Оплата

Freedom Pay выбран как платёжный провайдер, но в публичной статье перечислять конкретные способы оплаты следует только после подтверждения production-конфигурации merchant account.

### Сведения о пакете

До публикации продукта нужно подтвердить, что UI и API надёжно показывают:
- покрытие;
- тип трафика;
- срок;
- правило начала действия;
- дневные ограничения;
- поддерживаемые сети;
- возможность пополнения;
- сведения, необходимые для ручной настройки точки доступа.

## Источники истины

Порядок приоритета:

1. закон и утверждённые юридические документы;
2. подтверждённые решения владельца продукта;
3. production API и интерфейс eBanano;
4. актуальная документация поставщика;
5. архитектурная документация;
6. старый Help Center.

Figma используется только для понимания сценариев и состояний интерфейса. Данные и тексты макетов не считаются фактами.


## Голос и тон

2026-09-18 весь русский канонический Help Center прошёл отдельную редактуру по [HELP_CENTER_VOICE_AND_TONE.md](HELP_CENTER_VOICE_AND_TONE.md).

Применены два режима одного голоса:

- обычные сценарии — живой, разговорный тон с характером;
- деньги, возвраты, ошибки, безопасность и потеря доступа — тот же голос, но спокойнее и без шуток.

Из публичного текста убраны:
- канцелярит;
- мета-комментарии о документации;
- показная эмпатия;
- рекламные формулировки;
- внутренние обсуждения старых правил;
- формулировки, которые заставляют пользователя сначала классифицировать собственную проблему.

Базовый принцип: говорить как знакомый, который хорошо разбирается в eSIM и сразу показывает, что делать дальше.
